### 회원·사용자별 기억

- [x] **초대·로그인** — 가입은 초대코드 → 휴대폰 → SMS 인증번호. 로그인은 휴대폰 → SMS 인증번호. 회원도 초대코드를 발급하며 코드당 최대 3명이 가입한다. 개발·운영 회원은 분리한다.
- [x] **기억 저장 방향 확정** — 별도 on/off가 아니라 가입 시 개인정보·민감정보 항목을 각각 확인한다. 기존 회원도 현재 버전 확인이 필요하다. 현재 구현 문구는 개발용 초안이며 운영 확정 동의서가 아니다.
- [ ] **기억 기능 배포** — 텍스트 요약·임베딩·개인별 조회와 동의 게이트를 작업 브랜치에 구현했다. 개발 DB만 적용, 웹 배포·활성화 전. `text-embedding-3-large` 1536차원, 요약은 Runyour 모델을 사용한다. [구현 상세](MEMORY.md).
- [ ] **음성 기억·관리 화면** — 음성 기억 연결, 기억 조회·삭제 UI, 프로필 서버 저장은 후속 작업이다.
- [ ] **보관·파기** — 탈퇴 전 보유·탈퇴 후 1년 보관 요청은 목적·근거 검토와 실제 탈퇴·자동 파기 구현이 필요하다. 현재 구현 완료로 간주하지 않는다.
- [ ] **공용 모델 학습** — 모든 사용자에게 적용할 모델 개선은 별도 학습 목적·동의·처리 절차로 설계한다. 개인 기억 저장만으로 모델이 자동 학습되지는 않는다.

### 🎙️ AI 대화(음성·글)

음성: 말하기 → 글로 바꾸기(STT) → AI 답변 → 목소리로 읽기(TTS). 글: 메시지 입력 → 서버 API → AI 답변.

- [x] **어떤 AI·음성 서비스를 쓸지** — OpenAI realtime `gpt-realtime-2.1-mini`. 전화하듯 바로 듣고 바로 답한다. 진짜 키는 서버에만 두고, 브라우저는 임시 키로만 연결한다.
- [x] **글 대화 서비스** — Runyour AI의 `openai/gpt-5.6-sol`. `/api/chat`을 통해 JSON으로 요청·응답하고, 서버는 `/responses`와 추론 수준 `medium`을 사용한다. 마이크 권한·WebRTC는 사용하지 않는다. 서버의 `RUNYOUR_API_KEY`를 사용하며 음성용 `OPENAI_API_KEY`와 분리한다.
- [x] **대화를 어떻게 시작하고 끝낼지** — 홈의 음성 버튼은 홈을 유지하면서 음성 연결을 시작한다. 몽글이가 먼저 인사하며 인사 재생이 끝난 뒤 마이크 입력을 연다. 종료(X)는 연결을 닫고 홈 기본 상태로 돌아간다. 말풍선 버튼은 홈의 입력창만 펼친다. 닫기(X)·Escape는 입력창과 말풍선을 숨기고 기본 홈으로 돌아가며, 다시 열 때 대화와 초안을 유지한다.
- [x] **글·음성 전환** — 글 입력창을 열면 기존 음성 연결을 닫는다. 글에서 음성으로 바꾸면 별도 Realtime 세션을 시작하며, 이전 글 맥락은 음성 모델에 자동 전달하지 않는다. 음성 모드에서 마이크를 쓸 수 없으면 연결을 닫고 홈의 글 입력창을 연다.
- [x] **홈 음성 모드** — 몽글이를 같은 자리에서 확대하고 오른쪽 아래 버튼을 종료(X)·마이크 토글 컨트롤로 펼친다. 연결·듣기·응답 대기·말하기를 구분하며, 실제 마이크가 수신 준비된 경우에만 듣기 모션을 표시한다. 연결 실패 시 듣기 모션을 멈추고 오류·재시도를 제공한다. 화면의 파형은 입력 음량 측정값이 아니다.
- [x] **몽글이 반응** — 기본·입력 집중·듣기·응답 대기·말하기 상태에 맞춰 얼굴과 몸이 움직인다. 입력창 포커스나 작성 중인 글에는 집중 상태를, 실제 연결 상태에는 해당 동작을 표시한다. 오류·음소거 상태를 구분하며, 입력 내용의 감정을 분석하거나 추측하지 않는다. 동작 줄이기 설정에서는 반복 모션을 끈다.
- [x] **소리 내기 어려울 때를 위해 글 입력도 둘지** — 둔다. 마이크를 못 쓰면 글 입력이 자동으로 열린다.

### 홈의 대화 진입

- [x] **하단 구성** — 항상 노출되던 텍스트 입력창을 없앤다. 왼쪽에는 파일 첨부(+), 오른쪽에는 글로 이야기하기(말풍선)와 음성 대화(마이크) 버튼을 둔다.
- [x] **글로 시작하기** — 말풍선 버튼을 누르면 홈의 헤더·배경·몽글이를 유지하고 하단 입력창만 펼친다. 메시지는 같은 홈의 말풍선으로 표시한다. 입력창을 여는 것만으로 API를 호출하지 않고, 전송할 때 최근 대화와 새 메시지를 서버에 보낸다. 모바일 키보드에 맞춰 입력 영역 높이를 조절한다.
- [x] **메시지 전송 결과** — 응답 대기 중 사용자 글을 임시 말풍선으로 보여 준다. 성공했을 때만 사용자 글·답변을 기록하고 입력을 비운다. 실패하면 입력을 유지하고 오류를 표시하며, 재시도 시 실패한 글이 중복되지 않는다.
- [x] **메시지 입력** — 빈 글은 보낼 수 없다. 응답 대기 중에는 입력 수정·중복 전송·음성 전환을 막는다. Enter는 전송, Shift+Enter는 줄바꿈이며 한글 조합 중 Enter는 전송하지 않는다. 실제 API 응답 대신 임의 답변을 보여 주지 않는다.
- [x] **파일 첨부 범위** — 기기에서 파일을 선택하고 이름·용량을 확인하는 UI만 제공한다. 파일 더 선택하기와 선택 해제가 가능하며, 파일 선택을 취소하면 기존 목록을 유지한다.
- [x] **파일 처리** — 파일 메타정보는 홈의 임시 상태에만 보관한다. 같은 홈 안의 글·음성 모드에서는 유지하고 도움받기·내 기록 등으로 홈을 벗어나면 사라진다. 파일 내용을 읽거나 영구 저장·업로드·AI 전송하지 않는다. "파일 전송 기능은 준비 중이에요"를 안내한다.

### 🤝 도움받기

실제 사람인 상담사의 이용 안내·프로필·통화 흐름을 살펴본다. 현재는 화면과 탐색 흐름을 검토하기 위한 UI 프로토타입이며, 실제 상담 연결은 제공하지 않는다.

- [x] **메뉴명** — 진입 메뉴·버튼은 "도움받기"로 통일한다. 내부 화면은 상담 안내·도움받기 목록·상담사 프로필·통화 미리보기로 구분한다.
- [x] **누구를 고르는지** — AI 상담사가 아닌 실제 사람인 상담사.
- [x] **진입 경로** — 홈 메뉴 또는 대화 중·종료 후 "도움받기" 버튼에서 상담 안내로 진입한다. 새 대화나 AI의 안내 없이도 직접 열 수 있다. AI 대화 중 진입하면 기존 마이크·소리를 끈다.
- [x] **상담 안내** — 진입할 때마다 표시한다. 건너뛰기와 상담사 둘러보기는 모두 목록으로 이동하며, 안내 확인 여부 저장·동의 수집은 하지 않는다.
- [x] **화면 흐름** — 상담 안내 → 상담사 둘러보기 또는 건너뛰기 → 상담 주제 필터 → 상담사 카드 클릭 → 프로필 바텀시트 → 이야기하기 → 상담사 통화 미리보기. 미리보기 종료는 같은 필터의 목록과 원래 카드로 돌아간다. 목록에서 뒤로 가면 안내, 안내에서 뒤로 가면 진입했던 화면이다.
- [x] **카드 동작** — 누르면 바로 프로필 바텀시트를 연다. 체크박스·선택 상태와 목록 하단의 별도 프로필 보기 버튼은 두지 않는다.
- [x] **이야기하기** — 프로필 바텀시트 하단에 스크롤해도 보이는 버튼을 둔다. 누르면 별도 전체 화면인 상담사 통화 미리보기로 바로 이동한다.
- [x] **통화 미리보기** — 예시 상담사 이름·주제와 연결되지 않음을 표시한다. 마이크·스피커는 화면 상태만 바꾸며 실제 통화·녹음·오디오 출력·마이크 권한 요청·타이머는 없다. 종료·뒤로·Escape는 목록으로 돌아간다.
- [x] **현재 구현 범위** — 상담 안내, 예시 상담사 탐색·프로필 조회, 통화 화면 미리보기. 실제 상담사 조회 API, 연결 대기, 상담 연결, 예약·결제, 리포트 공유는 포함하지 않는다.
- [x] **예시 데이터 표기** — 실제 활동 중인 상담사로 오인되지 않도록 예시임을 표시한다. 확인되지 않은 경력·자격·후기·요금은 만들지 않는다.
- [x] **언제 안내할지** — AI가 대화 내용을 보고 전문가 도움을 선택지로 안내한다(`show_get_help`). "전문가와 이야기해 보는 것도 방법" 정도로만 안내하고 진단하거나 예약·연결이 가능하다고 말하지 않는다.
- [x] **제거하는 기능** — 기존 정신건강의학과 검색, 위치 권한 요청, 반경 검색, 병원 전화·지도 링크.
- **준비 중인 상담 과정** — 원본 기획의 상담 안내 → 상담사 찾기 → 연결 대기 → 앱 내 음성 상담 → 종료를 안내 화면에서 설명한다. AI가 참여하지 않는 사람 상담이 목표이며, 연결 대기와 실제 상담 기능은 구현하지 않았다.
- [ ] **실제 상담사 데이터** — 확보 경로, 자격 확인 기준, 프로필 검증·관리 방식.
- [ ] **실제 상담 운영** — 앱 내 음성 통화 구현·운영, 제공 시간·비용, 예약·결제 정책.
- [ ] **마음 리포트 선택 공유** — 원할 때만 공유하는 방향이며 공유 범위·동의 방식은 미정이다. 현재는 준비 중 안내만 있고 실제 리포트 공유는 하지 않는다.

### 📒 내 기록 (MVP 예외로 추가)

- 몽글이 프로토타입 "내 기록"의 하루하루 탭만 옮겼다. 대화를 날짜별 카드로 보여 준다.

### 공통 화면 기준

- **화면 크기** — 기존 제품 프레임을 유지한다. 너비는 브라우저에 맞추되 최대 430px, 높이는 브라우저 전체 높이(`100dvh`)이며 최소 640px로 유지한다. 긴 콘텐츠는 화면 안에서 스크롤한다.
- **디자인 시스템** — SEED Design의 타이포그래피·간격·라운드·모션 파운데이션을 사용한다. 컬러·그라디언트·캐릭터는 기존 제품 표현을 유지한다.
- **인터랙션** — 버튼 눌림, 선택 상태, 화면·시트 진입과 퇴장에 부드러운 전환을 적용한다. 사용자의 동작 줄이기 설정을 따른다.

## 5. 꼭 확인할 것

- 자살·자해 같은 위기 표현이 나오면 자살예방상담전화 **109**를 바로 안내한다. AI 답보다 먼저 띄운다.
- 글 전송 직전의 키워드 검사와 글 API의 위기·도움받기 플래그를 함께 처리한다. API 요청이 실패해도 받은 안전 안내 플래그는 유지한다.
- AI는 진단하지 않고, AI라는 걸 알린다.
- 도움받기의 예시 프로필은 실제 상담 서비스를 제공하지 않는다. 이야기하기 버튼을 눌러도 예약·결제·연결 완료로 표시하지 않는다.

다음은 향후 의료기관 연계를 도입할 때 다시 확인할 기존 검토사항이다. 현재 도움받기 화면의 기능 요건은 아니다.

- 병원 연결로 영리 목적의 환자 소개·알선을 하면 안 된다 (의료법 27조 3항). 병원에서 건당 수수료를 받는 구조는 피한다. 특정 병원을 추천·우선 노출하지 않는다.
