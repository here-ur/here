# 계정별 정원·라이브러리 저장

대상: 개발 서버 `here-dev.vercel.app`, Supabase `mwjwfumpxdlllikcdvkh`.
마이그레이션: `0016_account_activity.sql`. 운영 적용 없음.

| 테이블 | 보관 항목 | 식별 기준 |
|---|---|---|
| activity_days | 날짜별 발화·답변 수, 시간대, 제한된 키워드 집계, 위기 표시 | 회원 + 날짜 |
| activity_choices | 씨앗, 사용자가 고른 하늘, AI 하늘·재시도 시각, AI 하늘 선택 설정 | 회원 + 종류 + 날짜 |
| practice_events | 완료·나중에·닫기 기록 | 회원 + 날짜 + 실천 + 동작 |

- `auth.uid()` 기준 RLS. 다른 계정 조회·직접 쓰기 차단.
- 기존 회원 여부 및 현재 대화 저장 동의 확인 후 RPC 쓰기 허용.
- 계정별 브라우저 캐시는 즉시 표시용. 변경은 계정별 outbox에 보관 후 재전송.
- 로그아웃·계정 전환 중 도착한 응답은 다른 계정 캐시에 적용하지 않음.
- 첫 접속 시 기존 기기 기록 이전. 하늘·씨앗의 기존값은 서버 값이 없을 때만 가져옴.
- 명시적 변경만 시간순 적용. 실천은 날짜·종류·동작별 합집합. 재전송 중복 없음.
- 서버 통계는 UI의 최근 한 페이지가 아니라 계정의 보관 중인 대화 전체를 페이지 조회해 집계. 날짜·시간대는 한국 시간 기준.
- 대화 저장 뒤 백그라운드 집계. 실패한 경우 다음 활동 조회 때 다시 집계.
- 30일 원문 만료 시 이미 저장된 날짜별 통계는 축소하지 않음. 원문이 없는 예전 기기들의 집계는 중복 여부를 재구성할 수 없어 가장 큰 집계를 유지하며 단순 합산하지 않음.
- 활동 기록은 기존 기기 정책과 같은 최대 365일. `here-activity-retention` 작업이 매일 00:15 UTC에 만료분 삭제. AI 하늘 사용 설정은 유지.
- 동의 철회 시 활동 데이터 삭제. 회원 삭제 시 FK cascade. 탈퇴 후 1년 보관 정책의 구현과는 별개.
- 실천 데이터 저장 기반만 포함. 현재 실천 화면은 시안이며 이번 작업에서 정식 메뉴로 추가하지 않음.
- 초대코드·친구 관계 재설계, 탈퇴 보관 정책, 독립 요약 재시도 작업은 이 변경 범위에 포함하지 않음.

검증: PGlite DB 테스트(계정 격리·동의·중복·오래된 변경·보관기간·철회), outbox/응답 병합 테스트, 1,000건 초과 페이지 집계 테스트. 실제 서로 다른 두 계정/기기의 사용자 수동 테스트와 자동 검증은 구분.
