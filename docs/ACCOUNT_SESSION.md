# 로그인 유지 · 캐릭터 설정

- 적용 대상: 개발 브랜치. 운영은 별도 반영
- 세션: Supabase SSR의 호스트별 쿠키 저장. HTTPS Secure / SameSite=Lax / Path=/
- dev 브랜치 신규 임시 배포 홈: `here-dev.vercel.app`으로 307 이동. 고정 주소의 기존 세션 사용. 기능 브랜치·운영·API 제외
- 재접속: 루트 Proxy에서 만료된 액세스 토큰 갱신 → 브라우저에서 사용자·회원 검증
- 기존 세션: localStorage → 쿠키 1회 이전. 기록·캐릭터 캐시는 계정별 유지
- 인증 오류: 401/bad_jwt는 1회 갱신·재검증. 네트워크 장애는 재시도, 명시적으로 무효화된 세션만 로그인
- 로그인 화면: 신규 브라우저, 로그아웃, 저장소 삭제, 세션 무효화 시 휴대폰 번호와 비밀번호로 인증. 비밀번호가 없거나 잊었을 때 문자로 본인 확인 후 설정.
- 로그인 첫 화면: Figma `455:121`의 배치·그라데이션·영문 하단 문구를 사용하며, 배경은 사용자 제공 침실 고양이 영상으로 무음 반복 재생한다. 장식용 시간·통신·배터리 표시와 하단 홈 바는 사용자 요청으로 제거했다. 흰색 휴대폰 로그인 / 검정색 회원가입 두 버튼을 사용한다. 회원가입은 휴대폰 번호(ID) → 문자 인증 → 비밀번호(8자 이상) 설정의 3단계로, 초대코드와 비밀번호 건너뛰기는 없다. 비밀번호 설정·재설정은 로그인 입력 화면에서 제공한다. 이메일·구글·애플 로그인은 사용하지 않는다. 약관 URL은 미정으로, 사용자 요청에 따라 하단 문구만 표시한다.
- 회원 등록: `0008_phone_password_signup.sql`의 트리거가 인증된 번호에 대한 실제 비밀번호 변경 후 `members`를 생성한다. SMS 가입 시 만들어진 임시 해시는 가입 완료로 인정하지 않고, 기존 회원·가입일·초대 관계는 보존한다. 인증 후 중단한 계정은 재접속 시 비밀번호 설정부터 이어간다.
- 예전 가입 경로 차단: `0009_disable_invite_signup.sql`은 `redeem_invite`·`invite_available`의 공개·비로그인·로그인 역할 실행 권한을 회수한다. 함수 본문도 false만 반환하므로 실수로 권한을 다시 줘도 회원을 생성하지 않는다. 기존 회원과 친구 관계는 유지한다.
- 초대장: 폐지된 가입 코드를 발급·안내하지 않고 앱 가입 링크를 공유한다. 기존 친구 목록은 유지하며, 링크 가입만으로 새 친구 관계가 자동 생성되지는 않는다.
- 비밀번호 정책: 가입·재설정·설정 화면의 최소 길이는 8자. here-dev의 Supabase Auth 최소 길이도 8자로 적용했다(2026-11-14). 운영 반영 시 같은 서버 설정이 필요하다.
- 권한 확인: 기존 Bearer 토큰 검증 + members + RLS 유지. 쿠키나 사용자 메타데이터만으로 접근 허용하지 않음
- 캐릭터 원본: Supabase Auth 사용자 메타데이터 `here_profile_v1` (`version`, `profile`)
- 프로필 항목: 닉네임, 캐릭터 이름, 모습, 배경 색, 목소리, 스타일, 액세서리
- 기존 캐릭터: 서버 설정이 없는 계정만 현재 브라우저 설정 이전
- 새 기기: 계정 설정 복원. 서버 조회 장애는 재시도, 온보딩으로 오판하지 않음
- 저장/초기화: 계정 저장 성공 후 화면 전환. 초기화는 서버에 명시적 null 저장, 오래된 캐시 재사용 방지
- 대화 기억: 기존 요약·임베딩 DB와 별개. 이번 변경으로 기억 삭제/초기화 없음
- 한계: 이전 버전에서 브라우저 설정이 이미 지워졌고 서버 저장도 없었던 캐릭터 설정은 복원 불가

## 검증

- 실제 Supabase SDK + 합성 응답: 만료 세션을 새로운 요청에서 갱신, 쿠키 저장, 다음 요청에서 SMS 없이 사용자 확인
- 계정 프로필: 로컬 캐시 없는 복원, 기존 캐시 이전, 조회 실패, 타 계정, 초기화, 저장 실패
- 가입 DB: 실제 `0001`·`0002`·`0007`·`0008`·`0009` 마이그레이션과 PostgreSQL로 유효한 예전 코드의 가입 차단, 비밀번호 필수 설정, 기존 회원 보존, RLS를 검증한다.
- 2026-11-14 실제 로컬 앱: 기존 계정에서 로그아웃 → 새로고침 후 로그인 화면 유지 → 사용자가 휴대폰 번호·비밀번호로 로그인 → 문자 없이 홈 진입을 확인했다. 초대장 링크 표시·복사도 확인했다. here-dev DB에서 예전 가입 RPC 실행 권한 회수와 비활성 본문, 새 가입 트리거 활성 상태를 확인했다.
- 신규 번호가 없어 실제 SMS 신규 가입 완료는 미검증이다. 사용자의 동의에 따라 실제 기기 검증은 기존 계정의 로그아웃·비밀번호 재로그인으로 진행했다. 자동 테스트 결과를 실제 신규 가입 성공으로 간주하지 않는다.
- 사용자 신고의 실제 장시간 재접속 실패는 현 시점에 직접 재현되지 않음. 서버 세션 설정은 시간 제한/비활성 제한 없음 확인
