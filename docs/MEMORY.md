2026-10-31 기준. 운영 배포용 개인정보 처리방침이 아니라 개발 구현·검증 문서다.

## 저장·회상 흐름

- 재방문 UX: 같은 브라우저·계정·동의 버전에서 서버 확인을 마친 경우 홈을 먼저 표시하고 뒤에서 재확인한다. 로컬 기록은 동의 버전만 담은 화면 표시용 힌트이며 권한 증명이 아니다.
- 서버가 미동의/철회를 반환하면 힌트를 지우고 필수 동의 화면으로 돌아간다. 다른 계정·버전에는 재사용하지 않는다. 저장소 사용 불가/최초 진입은 중립 로딩 후 서버 결과를 따른다. 세션 갱신을 포함한 확인 대기는 10초로 제한한다.
- 이미 확인된 사용자의 일시적 조회 오류로 홈을 다시 가리지 않는다. 대화·음성·기억 API의 서버 회원/동의 검사는 그대로 유지한다.

1. 회원·현재 버전의 개인정보/민감정보 확인을 통과한 텍스트 요청만 처리한다.
2. 최신 질문을 임베딩해 본인 계정의 관련 기억을 최대 5개 가져온다. 조회 제한 시간은 2.5초다. 검색 실패 시 기억 없이 기존 대화를 진행한다.
3. 실제 AI 답변을 성공적으로 생성한 경우에만 Next.js `after`로 저장 작업을 예약한다.
4. 최신 사용자 발언에서만 최대 3개 사실을 요약한다. 이전 발언·AI 답변은 재수집하지 않는다. 원문 근거 일치 검사는 의미 정확성이나 비식별성을 보장하지 않는다.
5. 요약을 임베딩하고 사용자 ID로 저장한다. 빈 요약은 임베딩 비용 없이 `skipped`, 실패는 `failed`로 기록한다. 저장 작업 제한은 35초다.

| 처리 | 설정 |
| --- | --- |
| 답변 | Runyour Responses, `CHAT_MODEL`, 추론 medium |
| 요약 | Runyour Responses, `MEMORY_SUMMARY_MODEL` → `openai/gpt-5.6-luna`, 추론 low, `store:false`. 채팅 모델과 독립 |
| 임베딩 | OpenAI `text-embedding-3-large`, float, 1536차원 |
| 키 | 요약 `RUNYOUR_API_KEY`, 임베딩 기존 `OPENAI_API_KEY`, 서버에서만 사용 |
| 검색 | 본인 ready 행만 cosine 유사도 > 0.30, 최대 5개. 임계값은 파일럿 값이며 품질 튜닝 전 |

단순히 데이터가 쌓인다고 모델이 학습되지는 않는다. 공용 모델 학습 데이터셋·학습·배포는 구현하지 않았다.

## 음성 기억

- `/api/voice-memory`: 개발 활성화·회원·현재 동의 확인 후 처리. 텍스트와 동일한 `conversation_memories`·요약·임베딩·RLS 사용. 새 테이블 없음.
- 확정된 사용자 받아쓰기만 자동 저장 요청. 부분 받아쓰기·AI 답변·첫 인사 제외. 별도 기억 요청 불필요. 음성 파일은 기억 DB에 저장하지 않음.
- `remember`는 `after` 작업 예약 후 202 반환. 저장 완료 보장 아님. 처리 결과는 DB의 `ready/skipped/failed`로 확인. 통화 종료 전에 완료된 발언의 저장 요청은 종료와 별도로 마무리.
- 세션 ID + 받아쓰기 이벤트 ID의 SHA-256으로 중복 방지. 같은 이벤트 재전송은 중복 저장하지 않고 다른 세션의 같은 발언은 구분.
- `recall_memories` 도구로 이전 글·음성 기억 조회. 관련 기억이 필요할 때 모델이 호출하며 매 발언 자동 조회 보장은 아님. 한 차례 발언당 최대 4회 도구 왕복. 이전 발언의 늦은 결과가 새 발언을 중단하지 않게 후속 응답 제한.
- 조회 오류 시 기억 없는 대화 유지. 인증·동의 거절 시 음성 종료. 원문 대신 요약을 결과로 반환하고 외부 지시문으로 취급하지 않도록 구분.
- 최초 앱 진입에 선택적 마이크 권한 안내. 허용 확인 후 모든 트랙 즉시 종료. 홈 첫 진입의 인사는 마이크 없는 수신 전용 연결로 재생 후 종료. 마이크 버튼으로 시작·재연결할 때는 인사 없이 입력 활성화.
- 홈 인사: 현재 홈 방문에서 한 번. 메뉴·기록·글/음성 대화 전환 시 중단, 복귀 시 반복 없음. 새로고침·새 앱 진입은 새 방문. 자동 재생 차단 시 최초 포인터/키보드 동작에서 재생 재시도. 브라우저 보안 정책 우회 없음. 숨겨진 탭·화면 이탈·60초 대기는 연결 정리.
- 요약 모델 변경은 새 작업부터 적용. 기존 Sol 요약·벡터·모델 기록은 재작성하지 않음.
- 2026-11-01 실제 마이크 검증: 가상 문장 “요즘 매주 수요일 저녁에 종이접기를 하고 있어.” → DB ready / Luna 요약 / 1536차원 확인. 새 음성 세션에서 “내가 요즘 수요일 저녁마다 뭘 한다고 했지?” 질문 후 종이접기 회상 확인. 통화 종료 확인. 최초 연결 시간은 미측정.

## 테이블·접근 제어

- `memory_consents`: 현재 개인 기억 동의 버전, 두 확인 항목, 확인·철회 시각.
- `memory_consent_events`: 이후 동의·철회·재동의 이벤트 이력. 기존 상태는 `snapshot`으로 구분하며 과거 이력을 추정하지 않음. 회원은 본인 이력 조회만 가능, 직접 추가·수정·삭제 불가. 회원 삭제 시 함께 삭제되며 탈퇴 후 1년 보존 구현이 아님. 공용 학습 동의와 별개.
- `conversation_memories`: 사용자 ID, 요약, 벡터, 모델/프롬프트 버전, 처리 상태, lease, 재시도 횟수와 시각. 원문·음성 파일은 저장하지 않는다.
- RLS로 본인 행만 조회한다. 앱은 service role 없이 회원 JWT로 요청한다. 변경은 소유자 검사를 하는 RPC만 허용한다.
- 동일 요청 메시지 배열의 SHA-256으로 중복 처리를 막는다. 완전히 같은 이력은 새 세션에서도 같은 요청으로 취급한다. 메시지별 이벤트 ID는 후속 개선이다.
- 사용자별 새 저장 작업은 시간당 30개까지. 채팅·음성 세션·음성 기억·홈 문구는 아래 분산 호출량 제한도 적용. SMS·IP·조직 전체 예산 제한은 별도.
- lease로 오래된 작업의 덮어쓰기를 막음. 동일 저장 작업의 재요청 최대 3회, 중단된 pending은 2분 뒤 재요청 가능. 실행 중 요약·임베딩의 명시적 일시 HTTP 실패만 자동 재시도. 서버 종료 후 재개하는 영속 큐는 미구현.
- 개별 삭제·동의 철회 시 요약과 벡터를 지우고 상태를 `deleted`로 남긴다. 지연 작업·재동의가 기존 삭제 기억을 복원하지 않는다. 해시·ID·상태 등 중복 방지 메타데이터는 남는다.

## 동의·관리 API

모든 경로에 회원 Bearer 토큰이 필요하고 응답은 `no-store`다. 사용자 ID는 요청 본문이 아니라 검증한 계정에서 결정한다.

| 경로 | 동작 |
| --- | --- |
| GET `/api/memory-consent` | 현재 버전 확인 필요 여부 |
| POST `/api/memory-consent` | 현재 version + privacy:true + sensitive:true가 모두 있어야 저장 |
| GET `/api/memories` | 본인의 삭제되지 않은 최근 100개 처리 결과 |
| POST `/api/memories` | `action:forget,id` 또는 `action:withdraw_consent` |

신규·기존 회원 모두 동의 게이트를 지난다. 별도 기억 on/off 토글은 없다. 현재는 SMS 인증과 초대코드 사용이 끝난 다음 동의를 받으므로, 여기서 이탈해도 회원 생성·초대 사용은 완료된 상태다. 운영 가입 동의 순서와 문구 확정 시 함께 검토해야 한다. 동의가 없으면 활성화된 환경의 텍스트·음성 API가 403으로 막히고, 확인 장애는 503으로 막힌다.

`/dev/memory-consent`는 로컬 개발에서만 볼 수 있는 화면 미리보기다. 실제 동의나 데이터 저장을 하지 않는다. 배포 빌드에서는 404다. 기억 조회·삭제·철회 UI는 아직 없다.

## 테스트와 아직 남은 검증

- 모의 제공자 테스트: 모델·차원·키 분리, 근거 없는 출력 거절, 미동의 외부 호출 차단, 실패 시 대화 유지, 성공 후에만 저장 예약.
- PGlite + pgvector 테스트: 실제 PostgreSQL 권한/RLS/RPC, A/B 계정 격리, 동의·철회, 중복 저장, 삭제 경합, 오래된 lease 차단. PGlite는 테스트용 의존성이며 개발 DB를 로컬로 대체하지 않는다.
- 요청 처리 테스트: 비JSON/초과 본문 거절, 느리거나 취소된 요청의 유효한 JSON 일부를 동의로 받아들이지 않음.
- 실제 API에 가상 선호 문장으로 요약·1536차원 임베딩 응답을 확인했다. 실제 회원 데이터는 사용하지 않았다.
- 2026-10-31 개발 배포에서 사용자 직접 동의 후 저장·회상 검증 완료. 가상 선호(아줄·따뜻한 보리차) 2건이 `ready`, 1536차원으로 저장됐으며 새로고침으로 이전 대화 메시지를 비운 뒤 두 선호를 회상했다. 보리차 문장에는 기억 요청이 없었고 자동 저장됐다. 실제 개인정보는 사용하지 않았다.
- 개발 DB의 `authenticated` 역할로 소유자 조회·검색 성공, 다른 합성 사용자 ID로 동일 행 조회·검색 0건을 검사했다. 읽기 검증 트랜잭션은 rollback했다. 두 실제 SMS 계정의 브라우저 로그인 비교 시험과는 구분한다. 별도로 PGlite에서는 동의한 A/B 회원 간 조회·수정·검색 격리를 검증했다.
- 가상 검증 기억 2건은 개발 계정에 남아 있다. 사용자 승인 없이 실제 계정의 기억·동의를 삭제하거나 철회하지 않는다.

## 개인화 홈 인사

- `/api/home-greeting`: 검증된 본인 계정·현재 동의·개발 기억 활성화 조건을 모두 만족해야 조회한다. 최신 ready 기억 20건 중 비민감 후보 최대 8건을 사용한다.
- Runyour가 요약에서 직접 확인되는 일상 취향·활동·계획 하나와 원문 근거 문장을 추출. 진행 중 활동·요리 계획·취미 탐색은 상태별 후속 질문, 단순 취향은 활동을 가정하지 않는 질문으로 연결. 근거 불일치·부정·완료·모호한 활동은 후속 질문 제외. 규칙 기반 검증은 보조 방어이며 모든 문맥 판별을 보장하지 않음.
- 재방문 기본 문구: “왔네! 요즘 어떻게 지내?” / 종이접기 활동 기억: “요즘도 종이접기 해? 최근엔 뭐 만들었어?” / 요리 계획 기억: “전에 말한 파스타, 만들어봤어?”
- API 자체는 음성·새 기억을 생성하지 않음. 홈의 기존 수신 전용 인사는 확정된 화면 문구를 동일하게 읽도록 연결.
- 건강·관계·경제·정치·종교 등 민감 맥락과 부정 취향을 우선 제외하고, 모델에도 금지 범위를 지정한다. 키워드·모델 분류는 완전한 민감정보 탐지 보장이 아니므로 운영 전 추가 평가가 필요하다.
- 첫 온보딩 완료: “너와 친해지고 싶어! 너에 대해 알려줘.” 재방문: 가벼운 안부·일상 화제·안전한 기억 소재 혼합. 기억 없음은 첫 만남으로 단정하지 않음. 건강·관계·일정·직장 이야기는 홈에 자동 노출하지 않음.
- 계정·한국 날짜별 안정적인 문구 선택. 기억 연결과 가벼운 화제를 섞고, 모델이 반환한 임의 문장을 그대로 표시하지 않음. “이야기 한 판”, “오늘의 첫 장” 등 광고식 비유 제거. 확인되지 않은 어제/주말 일정이나 캐릭터의 실제 경험을 만들지 않음.

- 검색 호출에는 일반 검색어만 전달. 대화 이력·개인 기억·회원 ID를 검색 요청에 붙이지 않음. 이름·건강·사연 제외 프롬프트, 전화번호·이메일·일부 식별번호/키 패턴 차단. 완전한 개인정보 탐지·익명화 보장 아님.
- `store:false`, 직접 URL 읽기·스크래핑 없음, 검색어·결과 DB 저장 없음. 기존 대화 브라우저 기록과 제공자 보관 조건은 별개. 검색 결과를 개인 기억에 저장하지 않음.
- 실제 `web_search_call` 완료와 HTTPS 출처 주석이 모두 있어야 성공. 검색 실패·출처 없음·미완료·과대 응답은 unavailable. 결과 내 지시문은 따르지 않도록 분리.
- 검색당 20초·128KiB·요약 6,000자·출처 5개 제한. 요청당 hosted tool 1회, 앱 발언당 검색 최대 2회. 서버 API 직접 호출에도 회원·동의·공유 호출 한도 적용.
- 검색마다 기존 chat 한도(20/분, 200/UTC일) 추가 차감. 채팅 답변 요청은 별도 1회 차감. 음성 검색도 같은 한도 사용. 검색 과금은 모델 토큰 외 도구 비용이 추가될 수 있으며 금액 상한이 아님.
- 개발 파일럿 조건에서만 도구 활성화. `/api/web-search`는 같은 조건 미충족 시 차단. 운영/main 반영 없음, DB 마이그레이션 없음.
- 채팅 답변·음성 전사에 반환 출처 링크 추가. 음성 자막을 꺼도 검색 출처 링크 표시. 새 발언·통화 종료 뒤 늦은 결과가 새 응답을 시작하거나 출처를 섞지 않도록 제한.
- 인증 실패 응답 no-store 통일. 인증 서비스 장애는 로그인 만료와 구분해 503, 잘못된 토큰 401, 비회원 403. 예외 상세 숨김. 서버 Supabase 요청당 5초 제한, 개인 기억 후처리에도 요청별 새 제한 적용.
- 실제 검색 전용 호출: Supabase 공식 문서 검색·출처 반환 확인. 실제 마이크 웹검색 발화 검증은 별도.
