# 사용자별 기억 — 개발 파일럿

2026-10-31 기준. 운영 배포용 개인정보 처리방침이 아니라 개발 구현·검증 문서다.

## 적용 상태

- 작업 브랜치 `feat/conversation-memory`. 운영 코드는 변경하지 않는다.
- `20261031010000_conversation_memory.sql`을 서울 `here-dev`에만 SQL Editor로 적용했다. `here-prod`에는 적용하지 않았다.
- `MEMORY_ENABLED=false`가 기본값이다. 현재 고정 개발 웹에 기능을 배포하거나 활성화하지 않았다.
- `MEMORY_ENABLED=true`, 정확한 `here-dev` Supabase URL, Production이 아닌 환경을 모두 만족해야 작동한다. 환경변수만 바꿔 운영에서 활성화할 수 없다.
- 초기 SQL 파일은 이미 수동 적용했다. migration 이력 동기화 없이 `supabase db push` 또는 기존 테이블 생성 SQL을 재실행하지 않는다.

## 저장·회상 흐름

1. 회원·현재 버전의 개인정보/민감정보 확인을 통과한 텍스트 요청만 처리한다.
2. 최신 질문을 임베딩해 본인 계정의 관련 기억을 최대 5개 가져온다. 조회 제한 시간은 2.5초다. 검색 실패 시 기억 없이 기존 대화를 진행한다.
3. 실제 AI 답변을 성공적으로 생성한 경우에만 Next.js `after`로 저장 작업을 예약한다.
4. 최신 사용자 발언에서만 최대 3개 사실을 요약한다. 이전 발언·AI 답변은 재수집하지 않는다. 원문 근거 일치 검사는 의미 정확성이나 비식별성을 보장하지 않는다.
5. 요약을 임베딩하고 사용자 ID로 저장한다. 빈 요약은 임베딩 비용 없이 `skipped`, 실패는 `failed`로 기록한다. 저장 작업 제한은 35초다.

| 처리 | 설정 |
| --- | --- |
| 답변 | Runyour Responses, `CHAT_MODEL`, 추론 medium |
| 요약 | Runyour Responses, `MEMORY_SUMMARY_MODEL` → `CHAT_MODEL` → `openai/gpt-5.6-sol`, 추론 low, `store:false` |
| 임베딩 | OpenAI `text-embedding-3-large`, float, 1536차원 |
| 키 | 요약 `RUNYOUR_API_KEY`, 임베딩 기존 `OPENAI_API_KEY`, 서버에서만 사용 |
| 검색 | 본인 ready 행만 cosine 유사도 > 0.30, 최대 5개. 임계값은 파일럿 값이며 품질 튜닝 전 |

단순히 데이터가 쌓인다고 모델이 학습되지는 않는다. 공용 모델 학습 데이터셋·학습·배포는 구현하지 않았다.

## 테이블·접근 제어

- `memory_consents`: 현재 동의 버전, 두 확인 항목, 확인·철회 시각. 버전별 불변 이벤트 전체 이력은 아직 아니다.
- `conversation_memories`: 사용자 ID, 요약, 벡터, 모델/프롬프트 버전, 처리 상태, lease, 재시도 횟수와 시각. 원문·음성 파일은 저장하지 않는다.
- RLS로 본인 행만 조회한다. 앱은 service role 없이 회원 JWT로 요청한다. 변경은 소유자 검사를 하는 RPC만 허용한다.
- 동일 요청 메시지 배열의 SHA-256으로 중복 처리를 막는다. 완전히 같은 이력은 새 세션에서도 같은 요청으로 취급한다. 메시지별 이벤트 ID는 후속 개선이다.
- 사용자별 새 저장 작업은 시간당 30개까지다. 전체 채팅·검색·SMS의 호출 제한은 별도 작업이다.
- lease로 오래된 작업의 덮어쓰기를 막는다. 동일 요청 재시도는 최대 3회이고, 중단된 pending은 2분 뒤 재요청할 수 있다. 자동 재처리·영구 작업 큐는 아직 없다.
- 개별 삭제·동의 철회 시 요약과 벡터를 지우고 상태를 `deleted`로 남긴다. 지연 작업·재동의가 기존 삭제 기억을 복원하지 않는다. 해시·ID·상태 등 중복 방지 메타데이터는 남는다.

## 동의·관리 API

모든 경로에 회원 Bearer 토큰이 필요하고 응답은 `no-store`다. 사용자 ID는 요청 본문이 아니라 검증한 계정에서 결정한다.

| 경로 | 동작 |
| --- | --- |
| GET `/api/memory-consent` | 현재 버전 확인 필요 여부 |
| POST `/api/memory-consent` | 현재 version + privacy:true + sensitive:true가 모두 있어야 저장 |
| GET `/api/memories` | 본인의 삭제되지 않은 최근 100개 처리 결과 |
| POST `/api/memories` | `action:forget,id` 또는 `action:withdraw_consent` |

신규·기존 회원 모두 동의 게이트를 지난다. 별도 기억 on/off 토글은 없다. 현재는 SMS 인증과 초대코드 사용이 끝난 다음 동의를 받으므로, 여기서 이탈해도 회원 생성·초대 사용은 완료된 상태다. 운영 가입 동의 순서와 문구 확정 시 함께 검토해야 한다. 동의가 없으면 활성화된 환경의 텍스트·음성 API가 403으로 막히고, 확인 장애는 503으로 막힌다.

`/dev/memory-consent`는 로컬 개발에서만 볼 수 있는 화면 미리보기다. 실제 동의나 데이터 저장을 하지 않는다. 배포 빌드에서는 404다. 기억 조회·삭제·철회 UI는 아직 없다.

## 테스트와 아직 남은 검증

- 모의 제공자 테스트: 모델·차원·키 분리, 근거 없는 출력 거절, 미동의 외부 호출 차단, 실패 시 대화 유지, 성공 후에만 저장 예약.
- PGlite + pgvector 테스트: 실제 PostgreSQL 권한/RLS/RPC, A/B 계정 격리, 동의·철회, 중복 저장, 삭제 경합, 오래된 lease 차단. PGlite는 테스트용 의존성이며 개발 DB를 로컬로 대체하지 않는다.
- 요청 처리 테스트: 비JSON/초과 본문 거절, 느리거나 취소된 요청의 유효한 JSON 일부를 동의로 받아들이지 않음.
- 실제 API에 가상 선호 문장으로 요약·1536차원 임베딩 응답을 확인했다. 실제 회원 데이터는 사용하지 않았다.
- 테스트 계정으로 로그인 → 직접 동의 → 저장 → 새 대화에서 회상하는 배포 환경 통합 검증은 아직 남았다. UI 동의를 사용자 대신 수락하지 않는다.

## 운영 반영 전 필수 후속 작업

- 현재 문구는 개발용 초안이다. 실제 개인정보 대신 가상 대화만 사용한다. 개인정보/민감정보 수집 필요성과 동의·국외 처리 고지를 검토하고 확정한다.
- 사용자가 요청한 탈퇴 전 보유·탈퇴 후 1년 보관은 미구현이다. 목적·근거와 파기 절차 확정이 필요하다. 현재 회원 삭제 FK는 기억도 즉시 삭제하므로 보존 정책을 구현한 것으로 간주하지 않는다.
- 기존 프로필·원문 기록은 계정별 브라우저에 남고 대화는 30일 보관한다. 기억 DB 원문 미저장과 별개이며, 내 기록 재설계 시 함께 정리한다.
- 음성 대화의 기억 저장·회상, 프로필 서버 저장, 기억 관리 UI, 품질 평가, 오류 관측·재처리·비용 제한을 구현한다.
- 모델 학습 목적·동의·처리·삭제 정책은 개인별 기억과 분리한다.
