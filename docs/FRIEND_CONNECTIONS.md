# SNS 가입과 분리한 친구 연결

- 적용: 개발 웹 `here-dev.vercel.app` / Supabase `mwjwfumpxdlllikcdvkh`
- 마이그레이션: `0017_friend_connections.sql`
- 가입: 카카오·구글 로그인. 친구 초대는 가입 조건과 별개.
- 연결: 초대장 생성 → 링크 전달 → 상대 로그인·온보딩 → 초대장 확인 → 직접 수락.
- 공개 범위: 서로의 닉네임·연결 날짜. 전화번호·이메일·대화·기억·하늘·정원 데이터 공유 없음.
- 초대 링크 기본값: 7일, 3명. 유효한 초대장 재사용. 발급은 계정당 하루 10개 제한.
- 발급 취소: 해당 링크만 무효화. 이미 연결된 친구 유지.
- 연결 해제: 양쪽 목록에서 제거. 사용한 초대장으로 재연결 불가, 새 초대 필요.
- 기존 `members.invited_by`: 가입 당시 유입 관계로 보존. 기존 친구는 신규 관계 테이블로 한 번 이전.
- 기존 `invite_codes`: 과거 가입 코드. 새 친구 초대와 분리, 가입 코드 기능 재활성화 없음.

| 테이블 | 역할 | 직접 접근 |
|---|---|---|
| friendships | 정렬한 두 회원 ID의 유일한 친구 관계 | 관계 당사자만 조회 |
| friend_invites | 발급자·무작위 초대 토큰·만료·취소·사용 수 | 전부 차단, 본인 발급 RPC |
| friend_invite_acceptances | 수락 이력·중복 사용 및 삭제 후 재사용 방지 | 전부 차단 |

- 쓰기: 회원 확인·`auth.uid()`를 사용하는 제한된 RPC만 허용.
- 초대 수락: 초대 행 잠금 + 두 회원 조합 잠금. 중복 수락·양방향 초대 중복 생성 방지.
- 로그인 전 받은 링크: 같은 탭의 세션 저장소에서 OAuth·온보딩까지 유지, 수락·보류 시 제거. 저장소 사용 불가 환경에서는 로그인 후 링크를 다시 열어 확인 가능.
- 공유: 사용자가 링크 복사·기기 공유창에서 직접 전달. 앱에서 자동 문자·카카오 메시지 발송 없음.
- 아직 준비 중: 하늘 공유·응원 메시지·안부 알림. 실제 데이터 공유 연결 없음.

검증: 초대 미리보기의 비변경성, 수락·상호 목록, 3명 한도, 중복·자기 초대·만료·취소, 연결 해제 후 재사용 차단, 기존 친구 이전, 익명·제3자 접근 차단.
